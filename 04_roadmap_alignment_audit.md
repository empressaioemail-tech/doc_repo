# Roadmap Alignment Audit

```
Version: 2026-06-02 (item 6 amended 2026-06-06: engine extraction unfrozen)
Status:  Living instrument. Updated as the roadmap moves.
Purpose: Test every roadmap item against the constitution and the calibration / sovereignty logic.
```

This is the instrument you audit the roadmap against to get tighter alignment. It does two things: it audits the current 90 day roadmap item by item, and it provides a reusable template for any future item. When the roadmap changes, this document changes. The constitution does not.

## The prioritization lens

Rank moves by impact and accelerate. The building is mostly done, so this is not a delete and concentrate exercise. Concentration is a build time constraint, it forbids splitting scarce build attention across competing builds, and it does not forbid shipping two finished things at once. Deletion logic applies only to unbuilt or genuinely adjacent work, never to the built apps. The substrate move ranks first because it makes every other move compound.

## The audit columns

For each item: which root it serves, whether it deposits into the flywheel or only withdraws, build or ship, the main drift risk, and the owner.

## The honest constraint to watch

Shipping two betas is cheap, iterating on two is not. If both feedback loops cannot run hot, name which beta gets weekly iteration and which one waits, rather than starving both. A neglected beta is a demo, and it costs trust with the peers it was opened to.
