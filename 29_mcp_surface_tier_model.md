# MCP surface tier model

> **Purpose.** Tier model for the product line MCP surfaces. Companion to [`08_tiered_access_model.md`](08_tiered_access_model.md), which settles the atom-level tier (Layer 1 free, Layer 2 paid, Layer 3 product-wrapper paid), and to [`14_pricing_framework.md`](14_pricing_framework.md) SDK-as-payment-substrate section, which settles the settlement layer. This doc settles how those tiers express through agent consumption of each product's MCP surface — who pays, what's included, what triggers paid, who gets the revenue share.
>
> **Status posture.** Cross-cutting principles and per-product structural rulings are accepted as commitments. Specific numeric values (per-call rates, included-volume thresholds, take rate within the 1-3% range from 14) remain Open per [`08`](08_tiered_access_model.md) and [`14`](14_pricing_framework.md) postures. Customer-visible UX and metering implementation details surface per product at MCP retrofit sprint time.

## Cross-cutting principles

Four principles apply across the portfolio. Premortem-cleared 2026-05-16 against the four structural commitments.

**Principle 1: Layer 1/2 at the MCP surface mirrors [`08`](08_tiered_access_model.md) atom-tier.** Any MCP call that returns only Layer 1 atoms is free at the catalog level. Any call that returns Layer 2 atoms (adjudication-record, per-reviewer-pattern, comparable-project-precedent, cross-jurisdictional-precedent traversal) triggers Layer 2 metering. The same atom-tier boundary the 08 doc settles applies whether the consumer is a human via UI or an agent via MCP.

**Principle 2: Within-tenant vs cross-tenant as the second axis.** Inside a Layer 3 product subscription (SmartCity OS, Cortex, Codex 1a, Codex 1b), MCP calls against the tenant's own data are included in the subscription. This includes the tenant's own Layer 2 atoms (their own adjudication records, their own per-reviewer-pattern) generated by their own use of the platform. Cross-tenant calls (one city's agent querying another city's data, one firm querying cross-firm precedent) escalate to Layer 2 paid per call.

**Principle 2 refinement: substrate MCPs vs product MCPs.** Principle 2 applies to product MCPs that carry mixed Layer 1 plus Layer 2 atoms (SmartCity OS, Codex 1a, Codex 1b, Cortex). Substrate MCPs that are Layer 1 only by design (Hauska MCP Server, which is the same technical surface as Codex code intelligence) use a volume-tier model with `accessPolicy` routing revenue share to source actors per principle 3. The within-vs-cross-tenant distinction does not apply because there is no Layer 3 product subscription wrapping the substrate MCP.

**Principle 3: SDK is the settlement layer, not the metering layer.** Metering happens at each product's MCP server (knows tenant, knows call type, knows accessPolicy on the consumed atoms). The Hauska SDK routes the money per [`14_pricing_framework.md`](14_pricing_framework.md) SDK-as-payment-substrate section. Take rate is in the 1-3% range per 14; specific number deferred to modeling work.

**Principle 4: Reasoning-call as the unifying accounting unit.** Per-product metering details differ in customer-facing presentation (per-seat plus bundled submissions for Codex 1a, per-seat for Cortex, per-query for code intelligence, included-in-subscription for SmartCity OS within-tenant), but the underlying unit of accounting is the reasoning call that consumed atoms. The metering record carries which atoms were consumed; `accessPolicy` on those atoms routes the revenue share. This is the substrate-level expression of the "sell reasoning, not data" structural commitment.

### Substrate MCPs (Hauska MCP Server / Codex code intelligence)

One technical surface, two brand hats per ADR-008 placement. The Hauska MCP Server is the substrate-layer MCP; Codex code intelligence is the Empressa-product brand label for the same `search_atoms` / `get_atom` / `list_jurisdictions` tool set. Free at Layer 1 by design per [`50:74-80`](50_hauska_mcp_server.md#L74-L80); Layer 2 paid atoms (adjudication-record, per-reviewer-pattern, comparable-project-precedent) deliberately do not appear in this MCP tool surface — they live in the Codex 1a / 1b plan-review surfaces.

Four-tier shape per [`50:67-72`](50_hauska_mcp_server.md#L67-L72), confirmed this session:

| Tier | Limit | Audience |
|---|---|---|
| Free / public | 1K calls/day/IP, 10K/day/key | Anyone with an LLM client |
| Developer Pro | 50K calls/day | Indie devs, AI startups |
| Team | 500K calls/day | Small firms, agent companies |
| Embedder License | Unmetered; per-jurisdiction terms | PropTech, code rewrite firms, outsourced plan review firms |

Specific dollar values per [`50:67-72`](50_hauska_mcp_server.md#L67-L72) remain Open per the 08 deferred posture.

Phase 0 revenue scenario decision per [`50:57-63`](50_hauska_mcp_server.md#L57-L63) selected this session: **Scenario B (self-serve paid tier)**. $30-150K Y1 estimate, $100-400K Y2 estimate, ~$60K/yr cost. Pays for itself. No BD hire. Tier scaffolding ships in Sprint 51 phases per [`50:206-222`](50_hauska_mcp_server.md#L206-L222). Decision record at [`_decisions/2026-05-16_hauska_mcp_server_scenario_b.md`](_decisions/2026-05-16_hauska_mcp_server_scenario_b.md).

Rate-limiting posture: API-key gated with a generous daily cap. Free signup; free use up to 1K/IP or 10K/key per day; paid above. Captures consumption signal per [`08`](08_tiered_access_model.md) "Conversion mechanics" section without breaking the free tier promise. Mitigates adversarial agent risk via key revocation rather than gating signup.

### ECI MCP

Non-commercial. Internal-only surface for the operator and authorized internal strategic agents. All atoms default to `platform-internal` scope per ADR-017. No metering, no revenue routing, no take rate. Procedure-execution atoms (ADR-013) generated by ECI MCP calls are internal-tenant and not routed for revenue share.

Endpoint placement: separate `mcp.internal.hauska.dev` (or equivalent) recommended per [`60:374-377`](60_eci_atomization.md#L374-L377) to avoid tool-surface pollution for external agents. Confirmed this session; not a tier-model question.

### Codex 1a MCP

Contractor / plan-review firm pays per seat. Default per [`47:184`](47_codex_plan_review.md#L184): $300/seat/month, hold private until two paid conversions close, pilots free. Each seat carries a bundled MCP call quota covering within-tenant calls (firm's own findings, firm precedent, the city's Layer 1 atomized code, firm's per-reviewer-pattern). Cross-firm precedent and cross-jurisdictional adjudication patterns meter as Layer 2 overage; revenue share to source firms / source cities per `accessPolicy`.

Agent calls (firm's internal AI workflow consuming Codex 1a MCP) meter against the firm's seat. The agent acts on behalf of the reviewer; this is reviewer activity. Future agent-service overage tier if firms scale beyond what reviewer seats cover.

Customer-facing unit: per-seat with bundled submissions per month, with overage above. Customers think in submissions; metering happens per-call internally. Matches existing 47 customer mental model.

Two doc-drift items in [`28:63`](28_mcp_first_product_design.md#L63) flagged for fix: "architect-side" should read "contractor-side" (1a is contractor / plan-review firm per [`47:42-49`](47_codex_plan_review.md#L42-L49) and [`47:124-128`](47_codex_plan_review.md#L124-L128)); "pay per submission" framing should align with per-seat plus per-call overage shape settled here.

### Codex 1b MCP

Two buyer paths, both valid.

**City-direct (Bastrop pattern).** City pays SmartCity OS subscription; Codex 1b MCP ships into SmartCity OS Plan Review. Within-tenant calls (city's own code, findings, adjudication records, per-reviewer-pattern) included in subscription. Cross-tenant (cross-city precedent, AHJ batch operations, cross-jurisdictional compliance tracking per [`28:96`](28_mcp_first_product_design.md#L96)) metered as Layer 2 overage to the querying city. Revenue share to source cities.

**Firm-direct (SAFEbuilt pattern per [`08:115-117`](08_tiered_access_model.md#L115-L117)).** Outsourced plan review firms use Codex 1b across cities they serve. Per-seat or per-jurisdiction license unit deferred to ADR-009 firm-tenancy. Within-firm-engagement calls included in firm license; cross-jurisdictional calls beyond the engagement set meter as Layer 2 overage to the firm. Revenue share to source cities.

Cross-jurisdictional buyer rule: whoever makes the call pays. City querying = city pays. Firm querying across cities they serve = firm pays. Multi-jurisdictional consultant or state agency = per their contract.

### SmartCity OS MCP

MCP retrofit and city-to-city data sharing are the same work per [`28:60`](28_mcp_first_product_design.md#L60). City pays existing SmartCity OS subscription. Within-tenant scope includes all city-internal atoms (operations, parcel intel, Codex 1b findings, citizen-connect records, digital-twin assets) AND the city's own Layer 2 atoms generated by their own use (adjudication records, per-reviewer-pattern). The city paid for the platform; their own Layer 2 atoms came from their own work; consumption of their own atoms is included.

Cross-tenant exposes aggregated / anonymized patterns only per [`30:57-61`](30_smartcity_os.md#L57-L61) and ADR-007 access scopes; raw cross-tenant records do not traverse. This is an enforcement boundary, not a tier boundary.

Cross-tenant buyer at v1: city only. External agent operators (developer's agent doing cross-jurisdictional due diligence, state regulator running multi-city audit) deferred to expansion via Hauska MCP Server Embedder License or a separate commercial relationship. Matches v1 customer base.

Customer-facing UX for cross-city queries: advanced Layer 2 opt-in surfaced in the UI with per-query overage billing. Honest about cost; explicit consent per query. Matches principle 4 reasoning-call framing. Bundled-into-higher-tier-subscription option rejected because revenue-share routing to source cities is harder with flat-rate access.

### Cortex MCP

Design / engineering firm pays per seat (default) or per-firm enterprise terms (option emergent for larger firms per [`08:115-117`](08_tiered_access_model.md#L115-L117) big-design-firms row). Pricing not yet pinned in any canonical doc; per-seat default consistent with Codex 1a ergonomics. Specific dollar values deferred per the 08 Open posture.

Within-firm-tenant scope includes the firm's own engagements, briefings, findings, render outputs, parcel intel for their projects. Bundled call quota per seat per month. Cross-jurisdictional Layer 2 calls (one firm querying multiple cities' code for a multi-jurisdictional project) meter as overage; revenue share to source cities.

**Cross-firm precedent is opt-in only.** Design firms compete on design quality and IP; precedent sharing is high-friction. Default: cross-firm precedent NOT exposed. Cross-firm Layer 2 metering activates only on opted-in firms with revenue share to source firm. Matches design-IP sensitivity; deviates from principle 2's default-cross-tenant-meters posture for this product specifically.

Revit add-in calls (architect's Revit session calling Cortex MCP via the add-in) use the same metering as direct MCP calls. Single metering surface; consistent reasoning-call accounting per principle 4.

Most natural agent use cases per [`28:72-73`](28_mcp_first_product_design.md#L72-L73): draft response letter, query constraint set, generate detail spec. Each is a reasoning-call.

### Revit Connector MCP

Two paths, each mapped to an existing ruling above.

**Internal Cortex add-in path.** Architect uses Revit Connector to pull Cortex intelligence into Revit. MCP calls meter against the firm's Cortex seat per the Cortex ruling above. Single metering surface.

**External multi-host embedder license** (opportunistic per [`28:74-77`](28_mcp_first_product_design.md#L74-L77)). Another host tool's vendor (AutoCAD integration partner, ArchiCAD plugin developer, Vectorworks add-in) licenses the MCP surface to deliver "Cortex-equivalent" experience in their host. Same shape as Hauska MCP Server Embedder License. Per-host or per-end-user-MAU terms; specifics deferred to first partner conversation per [`08:173`](08_tiered_access_model.md#L173).

## Conversion triggers

Summarized across products for cross-product visibility.

For substrate MCPs (Hauska MCP Server / Codex code intelligence): volume above free tier daily cap triggers Pro / Team conversion; production embedding triggers Embedder License conversation.

For product MCPs: cross-tenant calls trigger Layer 2 overage from day one (the customer sees the overage in their bill). Volume on within-tenant calls triggers seat-quota overage or seat-add conversation. Cross-jurisdictional queries surface as the most natural conversion path for firms working across multiple cities.
