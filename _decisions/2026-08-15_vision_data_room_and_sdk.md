# Decision

The 2026-08-14 Empressa positioning narrative is the highest-level vision. The Command Center data room is how questions 1 and 2 (who, what) become visible. The Hauska SDK is question 3 (how do I pay) and is not attached to the data-room path.

## Context

Operator handed the narrative in session 2026-08-15 as the vision that explains the SDK/data-room relationship, and confirmed ICC as the first real SDK customer. The CC-done WDLL (`_inbox/2026-08-15_a_wdll_cc_done_l15.md`) had already proposed a thin SDK subset (accessPolicy + product key + dual interface). This decision adopts the mountain and the mapping rather than leaving them in chat.

## Structural commitment check

- Sell reasoning, not data: the room shows evidence on every file; the SDK charges for consumption of that evidence, not for a blob.
- Confidence earned, not asserted: calibration and typed absence are question-2 properties of the room, not payment features.
- Dual interface: MCP is the machine face of the same room; CC is the human face. Payment rides the MCP paid tier only.

## Reasoning

If the SDK is wired into CC-done, we teach the stack that browsing truth is a checkout. The narrative says the opposite: plumbing moves value, it does not make anything true. The data room is the truth layer made contestable. The SDK turns on when a verified source (ICC first) is consumed by a paying caller.

## Reversal criteria

Reverse the altitude only if a later positioning narrative supersedes `_thought_leadership/04_positioning_narrative.md`. Reverse the mapping only if Command Center is re-ruled a paid agent surface.

## Dependencies

Companion: `_decisions/2026-08-15_icc_first_sdk_customer.md`. Unblocks freezing CC-done WDLL ruling 3 (SDK subset). Does not freeze WDLL rulings 1, 2, and 4 (file set, folder set, panel name).
