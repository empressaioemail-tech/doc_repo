# Decision

Brokerage V1 scope now includes `3b` property workspace collaboration, `3c` atomization start, `3d` paywall plus wallet metering, and `3e` admin session and viral graph baseline.

## Context

Inbox rollups from 2026-05-28 captured aligned evidence that these requirements are central to operator intent and product value, not optional follow-on polish. The prior sequencing decision intentionally queued these features post-launch to protect velocity. Operator direction now changes the constraint: V1 must include the collaboration, packaging, monetization behavior, and graph baseline.

## Structural commitment check

- Sell reasoning, not data: **green**. Shared workspaces and atomized packages still require evidence-backed reasoning with citations.
- Partnership-first sourcing: **green**. Scope change is product behavior and does not alter city data sourcing policy.
- Cost per jurisdiction: **green**. This is not a jurisdiction-onboarding expansion.
- Dual interface principle: **green**. UI workflow remains primary and atomization is explicitly tracked in V1.
- Focus queue rule: **yellow acknowledged**. Scope expands V1; non-critical backlog items must be deprioritized to protect delivery.

## Reasoning

Reopenable workspaces, attachments, and sharing are core trust and collaboration behavior for actual brokerage use. Atomization start is the shortest path to durable package portability and future graph/analytics leverage. Paywall behavior must preserve user confidence by avoiding lockout of prior work while gating new compute, and wallet increments align with low-friction trial economics. Admin graph visibility is a required operating lens for early viral-loop measurement, provided consent controls are enforced.

## Reversal criteria

- Revisit if expanded V1 misses pilot timeline by more than two sprint cycles without compensating pilot value.
- Revisit if consent or legal constraints block graph baseline from shipping safely in V1.
- Revisit if billing rail constraints prevent reliable wallet top-up behavior in V1.

## Dependencies

- Depends on deployed brokerage API routes and stable extension endpoint wiring.
- Depends on consent-aware event capture for share and graph edges.
- Depends on clear acceptance criteria per phase slice (`3b/3c/3d/3e`) in dispatches.
