### The shape of the fix (ruled at OPS-17 A-072)

An inline, classless `<script>` in `<head>` that reads `location.search` and stamps an attribute on the
ROOT element, plus attribute-keyed visibility rules in `web/shell.css`. Visibility is then decided by the
parser before first paint, so the flash is structurally impossible rather than merely faster.
Attribute-based, so the G-88 item-3 class gate stays satisfied — do not introduce a class.

### Five things you must MEASURE rather than reason about, because each can silently sink this

1. **Specificity.** The static `class="lens on"` and your attribute rule will both be live unless the
   attribute rule wins the cascade. Compute or test the resolved `display` for every one of the fifteen
   sections under each input, and assert exactly ONE is displayed. "It should win" is not a measurement.

2. **The whitelist is now a PAIRED CONTROL and needs a divergence test.** Your head script cannot
   `import` from `/staff-review.mjs` — an import makes it a module and a module is deferred, which is
   the whole defect. So it will carry its own copy of the valid lens ids, work ids, and the
   `city-manager` fallback. That is one rule with two implementations, which is the CTRL-1 shape this
   program has already paid for twice (DEV_PROCESS 2.4). Ship a test that reads the id sets out of
   `src/staff-review.mjs` and out of the inline script in `web/index.html` and asserts they are equal.
   It must fail if either side changes alone; prove that by changing one side and watching it fail.

3. **CSS cannot compare two attribute values**, so mapping "root says X" to "section with id X is
   visible" is an enumeration. Write it, count it, and state the count and the rule that keeps it in
   step with the section list. If you can key off something that does not need fifteen rules, take it,
   but only if you can show it works for all fifteen.

4. **An unknown lens must not paint nothing.** `?lens=bogus` resolves to `city-manager` in the module.
   Your head script must reach the same answer, or a bad deep link paints a blank screen before the
   module corrects it, which is a worse flash than the one you are removing.

5. **`applyLens()` must not go dead.** If the attribute now governs visibility and `applyLens()` only
   toggles `.on`, the class becomes decorative and any future JS-driven lens change silently does
   nothing. Keep the two in step (the cheap way is for `applyLens()` to write the same attribute) and
   assert it. Decide it deliberately and state the decision.
