### Why this exists, and it is the whole reason the item is on the card

A design pass translates React kit compositions into static markup. A kit composition emits **zero `id`
attributes, zero `hidden` branches and zero `data-*` hooks**. The product carries **94 distinct ids
page-wide**, **14 hidden elements**, and `web/app.js` makes **33 `getElementById` and 10

driven.

And nothing catches it. `test/_markup.mjs` in the kit normalises away exactly `id`, `hidden` and every

### The instrument

A test in `src/` that extracts the ADDRESSED set from `web/app.js` and diffs it against what the product

### Four traps, each of which will silently make this instrument vacuous

Take each one seriously. The failure mode here is not a red test, it is a green one that never looked.

**Trap 1: ids reach `getElementById` through helper functions.** `app.js` calls
`setText("cp-scope-lens", label)`, and `setText` is the thing that calls `getElementById`. A regex that
scans for `getElementById\("([^"]+)"\)` misses every id passed to a helper, so your addressed set is
short and the diff is green on a screen that is already broken. This is the same shape as the runtime
class extractor's blindness to classes passed as function arguments, one layer up. Resolve id-taking
helpers to their call sites, and **state your resolution method where the number is reported**.

**Trap 2: some addressed ids are created BY `app.js`, not served.** An id that `app.js` both creates and
addresses must not be required in the static document, or the test is permanently red — and a
permanently red gate is a dead gate (DEV_PROCESS 2.0). Classify them, and make the classification
DERIVED rather than a hand-written allow-list wherever you can. Whatever exclusion set survives is part
of this instrument's contract and must be stated where its output is read, not buried in the source
(DEV_PROCESS 2.1). A hand-declared list that nothing recomputes is the `has_writer` defect this program
has already paid for.

**Trap 3: the served document is not only `web/index.html`.** `src/shell-homes.mjs` generates

`src/staff-map.mjs` and `src/staff-review.mjs` are served to the browser out of `src/`. Derive your
source list the way `src/ui.test.mjs` already does — from `server.mjs`'s `sendFile` call sites plus the
bake sources — rather than hardcoding it, so a new served asset cannot dodge the scan.
