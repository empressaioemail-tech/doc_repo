### Why this row exists

The gate G-95 built is good and it is not yet a control, because its number depends on two things nobody
declared. Both were found by rendering lanes measuring, not by the gate reporting them.

**1. The result is VIEWPORT-BOUNDED.** axe's `color-contrast` evaluates only what is in the viewport. Two
independent divergence tests on the same surface: R3 measured the Development services lens at **0 nodes
at 1440x900 and 2 at 1440x3000**; R2 measured **0 at 1440x900 and 2 at 1440x1200**. In every arm the node
count equalled the IN-VIEWPORT count. The gate runs at 900, so **"0 conformance nodes over 46 scans" is an
above-the-fold figure presented as an absolute one.** That is material to an Accessibility Conformance
Report, because an auditor does not scan at our viewport.

**2. The result is ENVIRONMENT-DEPENDENT.** R2 measured the gate **failing locally on Windows with 44
unresolved nodes and passing on Linux CI on the same SHA**. G-95's own adjudication already records the
environment dependence and measured it in the OPPOSITE direction. A ceiling that ranges 0 to 44 across two
operating systems is a control-design question, not a tuning one, and it is the single biggest threat to
the VPAT's credibility: the report has to survive someone else running the scan.

### What to do, and the shape matters more than the number

**Establish the mechanism before choosing a fix.** For the viewport: determine whether scanning taller
finds genuinely different violations or the same ones later, and whether a full-page scan is possible with
this axe build at all. For the environment: find WHY Windows and Linux disagree — font metrics, device
scale factor, headless shell version, subpixel rendering — and say which, with evidence. A fix chosen
before the mechanism is understood is a tuning exercise, and this program has paid for those.

Then make the gate state its own conditions:

- **Whatever the scan is bounded by must be DECLARED where the number is read.** If the answer is that the
  gate scans at N viewports, the report says so; if it is one, the report says which and why. A figure
  whose bound is not stated beside it is the DEV_PROCESS 1.2 defect and this one lands in a legal document.
- **The environment must either be pinned or its variance must be part of the contract.** If the honest
  answer is that only Linux CI is authoritative and a local run is indicative, say that and make a local
  run SAY it too, rather than letting a developer read 44 as a real number.
- **An unresolved check is not a pass and must not read like one.** Whatever number survives, the gate
  must distinguish "measured clean" from "could not settle".
