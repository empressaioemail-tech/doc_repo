(DC-1 through DC-9 + DC-13 all grade through it) and it currently fails both ways under load:
measured 2026-08-14 — a GET returned a DAYS-OLD view (195 satisfied cells: the pre-08-12 shape,
geometry 194 + zoning 1, while SQL against county_facet_coverage simultaneously showed flood 114 +
mud 134/75/45 present and correct), and a subsequent GET hung 300s with ZERO bytes while the atoms
drain ran. Root shape: the route computes heavy aggregation on-request (the equivalent mud-scorer
aggregation measured 44 minutes) and whatever per-instance state it holds can serve stale without
saying so.

1. A materialized ledger summary + grid (table or fast view feeding from county_rail x

   aggregation inside the request path.

   same discipline as countyRailRefreshCli) that scorers/planner invoke after scoring; optionally a
   cheap DB trigger if you can justify it at CP1. Recompute cost lives at write time, where the
   writer already knows state changed.

   `summary.servedAt`. A stale view must be VISIBLY stale, never silently plausible — that is the
   defect class that nearly read as a 211-cell regression tonight.

   behavior, and every DC-1..DC-9/DC-13 instrument read identically (parity test: materialized

   divergence with reason). The legacy compute path can remain behind an explicit query param for
   audit, never as the default.
