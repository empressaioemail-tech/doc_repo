# Make account entitlement readable without a parcel, and persist the billing interval

## Why this card exists

Two live problems share one cause: there is no way to read account-level entitlement without a parcel, and the billing interval is not stored anywhere.

1. Settings shows Access as "Not read" for everyone, including paid accounts. It passes a null parcelNodeId on purpose because Settings is account-scoped, and `GET /entitlement` REFUSES without one (`propertyExplorer.ts` around line 289 returns early when `parcelNodeId` is not a non-empty string).
2. The P-98 next-action rail's highest-value rung, `annual_upgrade`, is STARVED because nothing can tell it a subscriber is on monthly. `pe_user_entitlements` has no interval column: its columns are ownerUserId, tenantId, accessTier, devRole, entitlementSource, stripeCustomerId, updatedAt, subscriptionTier, seatsPurchased.

## Deliverable 1: billing interval, persisted

Add a nullable `billing_interval` to `pe_user_entitlements`. Migration (next free number), drizzle schema, and BOTH hardcoded table lists refreshed if the column touches them — check `lib/db/src/__tests__/integration/schema.integration.test.ts` and the schema fixture template. Hand-patch the fixture and say so; CI's drift check is the proof.

NULLABLE AND NEVER DEFAULTED. Absent means unknown. A DDL default of 'monthly' would be a fabricated fact about someone's billing, and it would make the rail offer "switch to annual" to annual subscribers.

Derive the interval from OUR OWN configured price ids, not from a Stripe API field. `pePaywallStripe.ts` already maps tier to an annual price id (the `STRIPE_*_ANNUAL_PRICE_ID` group) and has `stripePriceIdForPeTier(tier, interval)`. Write the inverse in the same file, from the same config, so one place owns the mapping. This deliberately avoids `current_period_end` and anything else whose shape depends on the Stripe API version, since there is no version pin anywhere in this repo and that is a separate unresolved problem.

FAIL CLOSED: a price id that matches no configured id yields null, never a guess. Write null rather than assuming monthly.

Persist it in the webhook where the tier is already resolved: `checkout.session.completed` and `customer.subscription.updated`. Do NOT invent a new write path; the tier write is already there and this rides with it.

## Deliverable 2: entitlement readable without a parcel

Make `parcelNodeId` OPTIONAL on `GET /api/property-explorer/v1/entitlement`. With a parcel, the response is byte-identical to today — that is a hard requirement and you should test it. Without one, return the account block (accessTier, subscriptionTier, entitlementSource, devRole, seatsPurchased, billingInterval) and OMIT the `property` block entirely rather than sending an empty or defaulted one.

An omitted property block and a property block full of falsy values are different facts; the client already distinguishes them and must keep being able to.
