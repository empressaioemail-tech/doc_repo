# 24_adaptive_ui

Canonical home for the adaptive UI principle: the consumption-and-presentation layer of the atom substrate, a portfolio-wide design discipline.

## Contents

- `adaptive_ui_vision.md` — the canonical vision (the why). Reshaped 2026-06-13 to current brand and the live render-mode substrate.
- `design_system.md` — the living design language (the how), grown from real design work.
- `README.md` — this index plus the pull-back loop.

## The pull-back loop

Chris (product designer) sharpens the adaptive UI visually in the product repos (`mox_demo` first, then `legacy-design-tools`). To keep this canon current without blocking his work:

1. Chris's agent maintains a living capture in the product repo (`mox_demo/docs/adaptive_ui_design_system.md`), with a clearly-marked "for pull-back to canon" section as design decisions land.
2. At session boundaries the planner pulls those captures into `design_system.md` here, reconciling and de-duplicating.
3. The vision doc changes only when the underlying principle changes, not on every visual iteration.

The demo repo is where design is sharpened; this folder is where it is canonized for reuse across every product surface.
