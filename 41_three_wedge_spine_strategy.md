# The three-wedge spine strategy

Ratified 2026-07-31. Replaces the "two wedge / Tier-1-vs-Tier-3" framing with the sharper THREE-wedge shape.

## THE UNIFYING THEOLOGY (one act, three entry points)
Every wedge is the SAME underlying act: **turn any of a customer's reality into the atom / node substrate.** Three expressions:
1. TWIN THINGS — physical assets (parcels, infra, utilities, a portfolio) → nodes.
2. PLAN REVIEW / DECISIONS — adjudications and operational decisions → calibrated atoms (the earning loop).
3. CONNECT DISJOINT SYSTEMS — a customer's scattered vendor data → atoms + node structure.
Through-line: "all data becomes atoms and node structure." Not three products — ONE substrate with three entry points. Every atom (a Bastrop adjudication, a Mox close decision, a PE pro's query) feeds the SAME calibrated reasoning moat, respecting sovereignty (private stays private; only anonymous/public-tier pools).

## THE THREE WEDGES (one spine, three buyers)

| | RE-PRO wedge | MUNICIPAL wedge | CUSTOM-BUILD (commercial) wedge |
|---|---|---|---|
| Buyer | the professional (agent/architect/investor) | the CITY (via SmartCity + Vertosoft) | a Mox-class operator (vertically-integrated commercial) |
| Surface | PE + MCP-v1 | SmartCity OS + plan-review-as-app | bespoke engagement on the spine |
| Value | "the buildable answer, cited" | "your civic reality off the island — decisions become durable, queryable, owned record" | "your assets twinned + systems connected + decisions atomized — data rails you own" |
| Money | REVENUE IN THE DOOR (near-term, built) | LONG MONEY (long sale, durable, network moat) | retainer + outcomes (parallel commercial proof) |
| Sovereignty | public-record read | tenant-private (Bastrop isolated) | customer-owned data (Mox bought the IPFS/data-rails framing) |
| All on | the same public spine | the same public spine | the same public spine |

## THE KEYSTONE: PLAN-REVIEW SERVES ALL THREE
Plan-review is the convergence point — build it ONCE, it serves:
- RE-PRO: the next PE surface after the buildable answer ("does this comply with code").
- MUNICIPAL: plan-review-as-a-SmartCity-app is HOW municipalities get it (Vertosoft-channel payload) AND the off-island write-back (adjudications → calibrated atoms) that makes the confidence commitment REAL for the first time + turns Bastrop into the first network node.
- ICC: the BIG ICC use case (does-this-comply-with-code) rides plan-review.
- The atom write-back from municipal plan-review CALIBRATES the reasoning that makes RE-pro answers trustworthy. Plan-review is the keystone of the whole arch.

## THE DURABLE SEQUENCE (not fast-tracking anything)
IMMEDIATE — PE-TO-MARKET = the revenue engine. Finish it: paywall unlock + Stripe/CRM + all-TX-in-map. Closest to cash, already built, funds + proves the public substrate. MCP-v1 rides alongside (PE-proven functions, metered).
PARALLEL / PREP (not sprinted, behind PE):
- PLAN-REVIEW APP — the keystone (serves RE-pro next-surface + municipal off-island + Vertosoft payload + ICC use case). Build once.
- BASTROP OFF-ISLAND WRITE-BACK — the thesis move: plan-review adjudications → calibrated atoms. Gated on ICC ingest + wiring the write-back. THE tension to manage: the city pulls toward "better dashboard" (warm/revenue/easy) vs the harder off-island move that is the actual thesis. Both proceed; only off-island earns the calibration commitment + builds the network.
- MOX CUSTOM-BUILD — same spine/theology for a commercial client; retainer+outcomes; proves the substrate on a paying commercial account in parallel. Lead Phase 1 with accounting monthly-close/variance (highest manual surface), parcel-intel as Phase-2 pocket.

## KEY GROUNDING FACTS (2026-07-31)
- SmartCity OS: live at Bastrop (Sylvia + Jaime operator-zeros), multi-tenant, an Empressa product surface. Strong operational AGGREGATOR (connects MyGov/OpenGov/Samsara/etc → dashboard + Compass AI). But it's an ISLAND — its reasoning doesn't flow to the spine as atoms yet. Honest-thin: citizen payments UI-only (no backend), and GovTitle/blockchain-records + digital-twin + IoT tiers DO NOT EXIST IN CODE — advertised, not built. The spine is what makes GovTitle/digital-twin REAL (fulfill the already-marketed promise).
- VERTOSOFT: public-sector distribution channel; live in ~1 month, onboarding now. Channel-ready fact, NOT fast-track pressure (municipal sales are long regardless).
- MOX: Austin multifamily operator (~300 ppl, 45 sites, 12k units); Miguel Arce (CEO) bought the SUBSTRATE (data rails/atoms/customer-owned-data), not a feature. Custom-build = the commercial expression of the same theology.

2. TOKEN/RECORD ROLE BOUNDARY — substrate-only vs substrate+attestation-to-chain-bridge vs further. Still UNDECIDED; the GovTitle/records/tokenization stories are what the spine makes real ON TOP — but how far we own the record-to-durable-environment bridge is open. SmartCity already MARKETS GovTitle (vaporware) — the demand + positioning slot exist and are empty.
3. PLAN-REVIEW KEYSTONE detail — what building it once actually requires + unlocks across all three wedges (the map-in-detail step, if we go there before sequencing execution).
4. MCP SELF-METERING PRICING (C1), ICC ACCESSPOLICY FIX (C2) — owed; cohere with PE pricing / do-regardless-of-sequence.
