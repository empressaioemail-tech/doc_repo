# 2. The operator's three items

**1. The connector card shows the old logo.** The card icon is not something this server sends: `serverInfo` carries no `icons`, `https://mcp.smartsite.cloud/favicon.ico` is a 404, and `/` is `Cannot GET /`. Whatever Claude paints there is a fallback. SDK 1.29 supports `icons` on `Implementation`. Fix: `new McpServer({ name, version, websiteUrl: "https://smartsite.cloud", icons: [{ src: "https://smartsite.cloud/apple-touch-icon.png", mimeType: "image/png", sizes: ["180x180"] }, { src: "https://smartsite.cloud/icons/icon-512.svg", mimeType: "image/svg+xml", sizes: ["512x512"] }] })`, plus `/favicon.ico` on the MCP host redirecting to `https://smartsite.cloud/favicon.ico` and `/` redirecting to `https://smartsite.cloud`. Assert in `server.test.ts` that the initialize result carries `serverInfo.icons` with the PNG entry. Ships as p557; reconnect required for the card to refresh. No decision needed.

**2. There is no "Ask Claude about this parcel" button.** It was never built, by rule: WDLL item 26 (I5 / A15) says Find listing history is the only ask-Claude button in v1. Under the ruled design Claude already holds the opened parcel, so the button is convenience, not access: it drafts `About 48021:xxxx (label): ` into the composer for the user to finish. Cheap (one `ui/message` draft, same guard pattern as listing), no tool, no I1 or I5 exposure. Needs a one-line amendment to item 26 naming it as the second ask-Claude button. Recommendation: yes, ship it in p557 with the icon. Operator call.

**3. No map rendered.** Two different things. A map (tiles, basemap) is out by ruling (WDLL "Out of both cards", connector item 18); the panel's picture is the parcel ring drawn from `draw.ring`. On these five parcels there is no ring because the bake has no geometry for them: `boundary geom: none`, `footprint geom: none`, five of five (the capture's D7). The gold parcel and the four O5 warm parcels draw a ring because they went through the depth-warm-verify-promote path; these five did not. So the panel is honest (`Parcel boundary unmeasured`) and the gap is coverage, not rendering. Routing: property seat, the warm cohort. Options: (a) warm the parcels users actually open (on-open enqueue, ring appears on the next read); (b) warm Bastrop city subdivisions as a cohort; (c) leave as is and say so in the description. Recommendation: (a) as a P-92 item, since a user's opened parcel is the strongest possible warm signal, with the honest line staying until the warm lands. If the operator wants an actual map in Claude, that is a reversal of a named ruling and a card, not a QA fix.
