# WDLL: P-85 Central Texas recorded documents, Records Request

Date: 2026-08-26  Status: approved  Operator approval: 2026-08-26 (shape ruled the same evening; scope broadened the same night)

Prior artifacts (DEV_PROCESS 3.3b): the T3 easement recon and ingest spec (inherited for the GIS instant sources), 49b (pipeline and cost model), the recorded-restrictions vision (instrument taxonomy), the 2026-05-29 R4 upload close (the write path this card reuses), the vision, job, and report modules named under `reuse`. The card began as easements only; the operator broadened it to every recorded document before dispatch. The planner's numbers are the planner's; reporting one wrong is a successful outcome.

## Done looks like

A Studio user on Smart Site opens any parcel in Bastrop, Travis, Williamson, Hays, Caldwell, or McLennan and chooses **Records Request** from the Reports area. The request is acknowledged and the run starts in the background. Instant sources (public easement GIS, anything already known) answer within the request; the clerk index search by subdivision, lot and block, legal description, and the parties on the appraisal roll, the acquisition of every instrument the index returns, the vision read, the type-appropriate extraction, and the corridor geometry for easements and plats run as a job with a record and a cost. When it finishes the user receives an email and the parcel's property records show the recorded documents ordered by recording date and filterable by type, each with its recording reference, parties, dates, image, and acquisition method; the clauses that bind the lot for easements, plats, and restriction declarations; the easement corridors drawn on the map with confidence and inputs; or a stated verdict that the index returned nothing in the scope searched; or that the search could not be completed and why. The chat reasons over the set with citations. Free and Solo users see Records Request as a Studio report, never a blank. Nothing is pulled around a paywall; every automated portal search runs only where that portal's terms were read and recorded as permitting it; every run is a row. The product never asserts title, priority, or a chain; it reports what the index returned and what the documents say. The public layer and the manifest cells wait for bulk acquisition and the Factory's conformant writer.

## Acceptance items

Order: Phase A now; Phase B is the product; Phase C and D later and operator-timed.

### Phase A: online now

1. **Portal terms read and ruled, per county.** For each of the six clerk portals (Bastrop Aumentum, Travis `tccsearch.org`, Williamson TylerHost and `publicsearch.us`, Hays `erss.co.hays.tx.us`, Caldwell, McLennan), the terms of use are captured verbatim into landing with the fetch date, and a row records `automated_search: permitted | tolerated | prohibited | unknown`, `login_required`, `image_purchase: price and method`, and the operator's ruling for that portal. No automated search runs against a portal whose row is `prohibited` or `unknown`. | check: six rows with quoted terms and dates; an unruled portal refuses in the job | grade: [ ]

2. **Instant sources are queried live, not landed.** No GIS layer is ingested on this card. At click time the run queries the public easement REST layers for the one parcel by geometry intersect (Round Rock `Easements/MapServer/0`, Cedar Park `Easements/FeatureServer/0`, City of Bastrop municipal easements, McLennan CAD `McLennanCADWebService` layers 9 and 10), applies the T3 ingest spec rules (city features only for parcels inside that city's limits; corridor width from `WIDTH` or the registry default; `recordingRef` from `DOC_NUM` or `Recordation_Num` where present, null where not), and records the query, the count, and the feature ids in the run. The Factory lands these layers later on the conformant shape (Phase D). | check: run row shows the live query and count; a control parcel outside city limits returns none; zero landing tables created | grade: [ ]

3. **Instant sources answer inside the request.** For a parcel with a live GIS hit, the acknowledgement already carries those easements labelled by source layer and recording reference; the clerk research continues in the background. | check: Round Rock lot answers under the request; Caldwell rural tract shows "researching" only | grade: [ ]

### Phase B: Records Request (Studio)

4. **Request, job, record.** From the Reports area, `POST` creates a `records_request_jobs` row (queued, running, complete, failed, needs-human) following `terrainJobWorker.ts`: one active job per parcel per user, concurrent enqueue loses, launch failure stamps `failed`. Every job carries the run fields the Factory uses (snapshot, scope, cost, termination) so it grades the same way. A job that cannot write its row does not start. | check: enqueue guard test; row before any work; launch-failed fixture | grade: [ ]

5. **Browser agent with a recipe per portal vendor; the whole index for the parcel, scoped and captured.** The job runs a headless browser (Playwright, Chromium) in a Cloud Run job and drives each portal through a versioned recipe (search URL, form fields, results table, image view and purchase flow): one recipe covers Williamson and Hays (both Tyler self-service), one each for Bastrop (Aumentum), Travis (`tccsearch.org`, vendor to be identified; it refused an automated fetch on 2026-08-26 and may need the human queue), McLennan, and Caldwell. The job searches by subdivision, block and lot (from the CAD roll), by legal description text where the portal indexes it, and by the parties on the appraisal roll (current owner and the prior owners the roll carries), across **all document types** over the portal's full electronic range; it does not filter to easements. For every search it stores a **full-page capture of the results page** (query as typed, result list, timestamp) as a hashed run artifact; that capture is the evidence behind `scopeSearched` and behind any `absent-verified` verdict. Queries, dates, counts, and capture hashes are written to the run. A portal ruled `prohibited` or `unknown`, a captcha, or a login prompt routes the job to `needs-human`. First proof is the Tyler recipe on Williamson and Hays. | check: run row shows queries, counts, and capture hashes; prohibited-portal and captcha fixtures route to needs-human; recipe version recorded; a fixture parcel with a deed, a deed of trust, a release, and an easement returns all four | grade: [ ]

6. **Instruments acquired: download where offered, purchase where sold, capture where only rendered, human where required; never around a paywall.** Every instrument the index ties to the parcel is acquired: free file downloaded; sold file bought through the portal's own purchase path at its per-page price with the cost written to the run; screen-only image captured full-page and labelled `capture`; person-required routed to a human clerk-run task with the exact instrument list while the run waits in `needs-human`. A run whose projected purchase cost exceeds the card's threshold pauses and asks the user before buying (the threshold is a product constant, recorded on the run). Every artifact carries its hash, portal, acquisition method (`download`, `purchase`, `capture`, `human`), and cost. A bot never drives a person's login. | check: artifact rows with method and hash per instrument; a Bastrop run produces a human task, not a bypass; a purchase records its fee; the threshold ask fires on a fixture | grade: [ ]

7. **Vision read with headers.** Each acquired image is read by the existing vision module (`attachedDocumentVision.ts`) and the extracted text carries its source and verification headers; a read that fails is recorded as failed for that instrument, never as "no document." | check: run artifacts per instrument; a deliberately blank page records a failed read | grade: [ ]

8. **Classification and extraction depth follow the type.** Every instrument lands as a `recorded_instruments` row with ADR-020 `instrumentType` (`easement`, `plat-restriction`, `cc-r-declaration`, `deed-restriction`, `lien`, or `other` with a `documentKind` for deed, deed of trust, release, notice, affidavit, lis pendens, power of attorney, memorandum of lease, mineral or royalty, association notice, until the substrate extends the enum), `recording` (instrument number, volume and page, recording date), parties as indexed, `sourceDocumentCid`, `appliesTo` (parcel plus plat or legal), `sourceAdapter: "records-request-v1"`, `verificationStatus: machine`, scoped to the requesting user like an upload. **Easements, rights of way, plats, and restriction declarations** additionally get `restriction_clauses` rows (`clausePath`, `bodyText`, structured fields for width, class, party, use limits, `confidence`, `sourceCitation`). **Deeds, deeds of trust, releases, liens, notices, and affidavits** get header facts only (parties, dates, amounts and cross-referenced instruments where stated) and no clause extraction on this card. Verified by violation: an instrument without a recording reference or an image refuses; a clause without a `sourceCitation` refuses. | check: rows per run by type; two refuse fixtures | grade: [ ]

9. **Geometry drawn as a Derivation.** Where an easement clause or plat note places a corridor, the job derives a corridor geometry from the parcel geometry and the clause, stores it under the clause's `constrains` reference with `derivesFrom` naming the clause and the parcel geometry, a method id, and a confidence; where it cannot place the corridor it says so and draws nothing. The map renders the corridor with its confidence; a corridor with no `derivesFrom` refuses. | check: three fixtures (rear-line utility easement, plat-drawn drainage corridor, unplaceable clause); refuse fixture | grade: [ ]

10. **Verdict when nothing is found.** A run that searched and found nothing writes a verified-absence record with `scopeSearched` (portal, queries, document types, date range) and shows that verdict in the property records; a run that could not search (portal prohibited, human task open, portal down) shows `lookup-failed` with the reason; the UI never shows an empty list. Unrecorded material (association bylaws and rules, unrecorded agreements) is named as outside the recorded index, never as absent. | check: three parcels, one per state; the unrecorded note renders | grade: [ ]

11. **Email on completion.** The user's email (from PE auth) receives one message on `complete`, `failed`, `needs-human`, or a purchase-threshold ask, naming the parcel and linking to its records; a transactional email provider is wired (operator picks it; none exists today), its sends are recorded on the run, and a send failure is a run event, not silent. | check: four fixture sends; failure recorded | grade: [ ]

12. **Reports area, property records, and chat.** Records Request appears in the Reports dropdown beside the feasibility study; the parcel's records view shows the documents ordered by recording date and filterable by type, each with reference, parties, dates, image link, acquisition method, and provenance chip; the clause and corridor detail for the constraining types; the verdict; the run's scope and cost summary. The chat cites instruments by recording reference; the MCP reporting gate returns the same set for the requesting user. | check: live probe on staging for a completed run; filter by type; chat citation test | grade: [ ]

13. **Studio gate, withheld is not absence.** The report resolves for Studio and Team; Free and Solo see it as a Studio report with no count and no verdict; the unresolvable-credential path is 401. Because PE's entitlement today is `free | paid` plus the per-property unlock, the gate reads the Stripe price id until the P-60 lane lands tier granularity. | check: four-caller matrix | grade: [ ]

14. **Cost and drift visible.** Per run: image fees, compute, human minutes, instrument count, and total; per portal: a daily canary search that, on failure, marks the portal `lookup-failed` for new runs until it passes. | check: run cost fields; canary observed failing on a deliberately broken selector | grade: [ ]

Bulk index acquisition stays in Phase C under ADR-027 with its TDI deferral intact. ## Do not

- Run an automated search against a portal whose terms row is `prohibited` or `unknown`.
- Filter the index search to easements; the request is for every recorded document.
- Fetch an image around a paywall or drive a person's login with a bot. Buy it, ask the user above the threshold, or queue a human.
- Show an empty document list. Three verdicts only.
- Serve a count or a verdict to Free or Solo.
- Assert title, priority, or chain anywhere. Report what the index returned and what the documents say.
- Write a public atom through `writePropertyAtomsBatch` on the old shape. Option A stands.
- Treat a vision read as authoritative; the headers stay on the text.
