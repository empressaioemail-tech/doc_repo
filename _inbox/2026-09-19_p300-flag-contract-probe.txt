WHY THIS EXISTS
The dry-run artifacts (close + predictions) carried the invocation
`node src/cli.mjs parcel-setback-cells --county <fips> --dry-run`. That form cannot run:
`--dry-run` is not a flag this job knows, and since P-229 the job REFUSES an unrecognized
argument before it opens a store. Dry run is the DEFAULT for this job (absence of --apply), so
the correct form has no flag for it at all.

TWO SIDE FINDINGS WORTH CARRYING FORWARD

1. `--county` is validated against IN_SCOPE_COUNTIES, which the merged source hardcodes to all six
   program counties including Hays (48209): "there is no county-specific carve-out left"
   (P-200, 2026-09-14, P-145 closed 2026-09-13). The cloudbuild YAML's header comment still says
   "Hays (48209) is structurally excluded (P-145 gate) -- there is no flag that can reach it",
   and that YAML still pins `_CONTRACT_VERSION: 1.30.0` with older engine/LDT SHAs. The COMMENT
   is stale relative to the source it ships with; the deployed generator is not something this
   lane can inspect. Read the source, not that comment, when deciding what can be scoped.

2. An unrecognized flag REFUSES rather than being ignored, which is P-229's fix and the reason the
   wrong `--dry-run` in these artifacts was caught by reading rather than by a silent no-op run.
   A silent version of this same mistake is what P-229 was: `--county=48209` was accepted and
   discarded on a production apply, so the run covered everything instead of the county asked for.
