# CP1: Cortex Custom Checkout

Adversarial inventory before the write. Read against `P:/tmp/ldt-checkout-3b` at `origin/main` `244567a5`.

## What is true in the code

1. `createPeSubscriptionCheckoutSession` (`pePaywallStripe.ts:180`) always posts hosted Checkout: `success_url` + `cancel_url`, then requires `session.id` and `session.url`. No `ui_mode`, no `return_url`, no `client_secret` read.

2. `createPePropertyUnlockCheckoutSession` (`pePaywallStripe.ts:307`) is the same hosted shape. Metadata is already `checkout_kind: property_unlock` + `parcel_node_id`. Webhook is untouched.

3. `StripeCheckoutResult` (`brokerageStripe.ts:62`) requires `checkoutUrl: string`. `clientSecret` does not exist. `stripePostForm` is the shared POST; it stays.

4. Route schemas (`propertyExplorer.ts` `PeCheckoutBodySchema` ~790, `PePropertyUnlockCheckoutBodySchema` ~891) accept `successUrl` / `cancelUrl` only. No `uiMode`. Unlock body is `{ parcelNodeId, successUrl?, cancelUrl? }`. Both unlock paths share one handler.

5. Simulated (no `STRIPE_SECRET_KEY`) always returns a hosted-shaped `checkoutUrl` pointing at `successUrl?simulated=1`. There is no custom simulated branch.

6. Missing price ID already throws `PeCheckoutConfigError` -> 503 `checkout_unavailable` before Stripe is called. Tier / interval / seats contract is already fail-closed. Do not touch it.

## Functions that will change

- `StripeCheckoutResult` — add optional `clientSecret`; make `checkoutUrl` optional so a custom 200 can omit it. Brokerage hosted callers still set `checkoutUrl`.
- `createPeSubscriptionCheckoutSession` — accept `uiMode?` and `returnUrl?`; branch hosted vs custom/embedded on the Stripe form and on the result shape.
- `createPePropertyUnlockCheckoutSession` — same `uiMode` contract.
- `PeCheckoutBodySchema` and `PePropertyUnlockCheckoutBodySchema` — optional `uiMode` enum + optional `returnUrl`. Unlock body stays `{ parcelNodeId, returnUrl? }` plus the existing hosted URL fields and `uiMode`.
- Route handlers that call the two create functions — pass `uiMode` / `returnUrl` through. Webhook (`handleStripeWebhook`) is not changed.

New helper in `pePaywallStripe.ts`: `peCustomCheckoutReturnUrl` (append `session_id={CHECKOUT_SESSION_ID}` when the caller did not already include the placeholder). Hosted `defaultPeCheckoutSuccessUrl` / `defaultPeCheckoutCancelUrl` stay as they are.

## uiMode default

Absent or `"hosted"` is today's hosted session: `success_url` + `cancel_url` + `checkoutUrl`. `"custom"` and `"embedded"` are the custom path: `ui_mode` + `return_url`, no `success_url` / `cancel_url`. Unknown strings are 400 via the zod enum. Hosted branch is not removed (item 3 keep).

## How simulated custom works

When `STRIPE_SECRET_KEY` is absent and `uiMode` is `custom` or `embedded`: return `mode: "simulated"`, a `sessionId` prefixed `cs_test_sim_…`, and `clientSecret` shaped `cs_test_…_secret_sim`. No `checkoutUrl`. `publishableKey` is whatever `stripePublishableKey()` already returns (null if unset). Do not return a hosted URL and call it custom.

When `STRIPE_SECRET_KEY` is present and `uiMode` is custom/embedded: post `ui_mode` + `return_url`; read `session.client_secret`; throw if missing (fail closed). Never emit `checkoutUrl` on that 200.

Missing price ID still 503 before either branch talks to Stripe.

## Falsifiers that must land

- Live custom session whose Stripe payload has id/url but no `client_secret` throws (violation).
- Custom 200 must not carry `checkoutUrl` (hosted-url-on-custom).
- `uiMode` absent and `uiMode: "hosted"` still return `checkoutUrl` (both directions).
- Unlock custom uses the same secret/no-url contract; metadata still `property_unlock` + `parcel_node_id`.
- Existing tier / interval / seats tests still pass.
