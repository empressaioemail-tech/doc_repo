## Reading the table honestly

**C9 (controls that cannot fail) is the largest class by a wide margin — 82 instances, roughly half still unfixed, and it was found almost exclusively by reading write-path code, never by measuring output.** This is not a coincidence; it is ENFORCEMENT's own standing claim ("every real defect in this operation to date was found by reading a write path... none were found by measuring output") independently reproduced at scale, by three independent readers of three disjoint source sets, arriving at the same class as the largest one in the register each time. It is also the class where the fraction of instances carrying a recurrence control that can actually fail is consistently under half — meaning even where this program has built a fix, it is usually built as a narrow patch to the one instance found, not as a standing rule that would catch the next occurrence of the same shape.

**C7 (label asserted by a constant) is the second largest — 40 instances — and it is disproportionately a *source-parsing* class**: the large majority of its instances are in the LDT source-parser register (PACS, Orion, TAD, StratMap ingestion), not in the bake/serve layer most of the rest of this register concerns. This means C7 is the class most likely to recur unchanged the moment a county with an unfamiliar CAD vendor or file format is acquired — exactly Milam's situation (CAD REST unproven; a new source shape has never been exercised against these parsers at all).

**C4 (missed sibling) grew the most of any class on the second and third folds-in (22 to 30 instances)** as two independent readers of OPS-16's amendment log and the earlier 2026-07-20–2026-08-20 sessions kept finding the identical shape — a hand-maintained list, or a rule implemented twice, with one copy fixed and the sibling forgotten — across completely unrelated features (checkout flows, tier gates, wrapper/consumer pairs, reaper heuristics). Several of its instances were fixed by building an explicit divergence test between the two siblings rather than a one-off patch — this is the pattern the smooth path generalizes for classes 4 and 5.

**C13 (serial discovery) has only 2 instances but both are fully controlled** — not because the class is rare, but because it is the *mechanism* the third-party review names as explaining most of the other classes' slow, one-at-a-time discovery pace. Once a full-population census replaces a sampled walk (which the third-party review's own Stage B3 proposal calls for and which the 2026-09-16 program scope document's `six-county-completeness.mjs` instrument is a working first instance of), C4, C8, and C18 discovery all speed up as a side effect — this is why the smooth path treats "replace every sampled instrument with a full-population one" as a single cross-cutting recommendation rather than a per-class one.

**Falsifier 1 check:** the six CTX classes (C1–C6) and the seventh (C7) each carry at least the instance count their own source documents name — C1 carries 3 against the session's 2 named instances; C4 carries 30 against the session's 2 named instances, recurring independently at least 17 more times across OPS-16, OPS-19, OPS-21, OPS-23, and the LDT/engine assumption registers; C5 carries 15 against the session's 1 named instance; C7 carries 40 against the third-party review's own "two instances found in an hour." **Every one of the seven exceeds its source count on every fold-in, three independent times, which is the falsifier's expected direction — a miss would have produced fewer, not more.**

**Falsifier 2 check:** satisfied independently at least four times, detailed in the unfixed list and the report below — most sharply by OPS-21's own text ("ninety-four cutovers have shipped, nobody has verified that a single legacy path has actually been retired") and by the empty-county gate (C9, BLK-017/018), which the record calls "designed" as early as 2026-09-13 and which this lane confirms via the 2026-09-16 program scope document is **still the live, unfixed gate defect three days later** — the single most consequential "called fixed, still broken" finding in this register, because every other class's recurrence-control claims are downstream of this gate actually working.
