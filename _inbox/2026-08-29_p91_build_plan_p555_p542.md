## 4.1 `get_smart_site` single id, cortex non-OK

| Cortex | MCP result text | `isError` |

Declared degradation, never silent: the `reason` field always travels. Arrays: cortex never 404s on an array (per-id `notFound` inside a 200); a 402 on an array refuses every id in `refused`.

## 4.3 Screen rows with rails (cortex `create_screen`, `list_screens(screenId)`)

Each resolved row gains `"stub": { "situs", "zoning", "landUse", "flood", "drainage", "envelope" }` in the five-state vocabulary already served by `assembleStubBody`, and `"stubRead": "ok" | "error" | "skipped"`. A bake miss maps to `unknown`, never `unread` (WDLL item 5; the saved list's `?? "unread"` is the violation not to copy). A stub read that throws leaves the rails `unread` with `stubRead: "error"`. Rows not reached inside the stub budget get `stubRead: "skipped"`. The screen carries `"stubsDegraded": true` when any row is not `ok`. Ambiguous and unresolved rows carry no `stub`. Nothing about stubs is persisted; the rows table is unchanged.

# 6. CP1 adversarial checkpoint (design, pre-build)

Claim: the design in section 1 is the only one that satisfies "lands in Claude's context" on today's host. Attack: the widget could self-fetch and push `ui/update-model-context`. Rejected because two open reports say Claude drops that channel on both surfaces (deep dive section 2), and the falsifier is cheap to run later (a "Reading widget context" step appearing in Claude's turn) without changing this cut.

Claim: rewriting a 402 as a result with `isError: false` is honest. Attack: it converts a refusal into a success. Answer: the `refused` array with `reason` is the declared state; Claude reads it; the panel paints it; nothing downstream treats an empty `parcels` with `refused` as a parcel. The alternative (`isError: true`) mounts no widget on Claude, so the user sees nothing and the board lies.

Claim: rails at first paint is I1-legal. Attack: it is data the conversation did not ask for. Answer: it rides the same tool result Claude receives; nothing is fetched by the iframe. It is more data in one call, not a side channel.

Claim: the stone clone's stale `artifacts/api-server` hunks are safe to set aside. Attack: they might carry something the leftover clone lacks. Answer: diffed this session, DIFFERENT, and the leftover clone is the newer base (889b1556 vs 006fd009) that p541 was built from. They are stashed with a message, not deleted.

What would prove the plan wrong before deploy: O2 or O3 in the deep dive (gold Open turning the board itself into the parcel; no second panel mounting for a 200 miss). Both are read on the Connect walk after p555 and would send this back to design, not to another URI.
