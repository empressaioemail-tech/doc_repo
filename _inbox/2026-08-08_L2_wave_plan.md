# L2 wave plan

Grouping and sequence for acquiring parcel geometry across the 235 Texas counties not yet loaded. Every figure below is computed from `_inbox/2026-08-08_SWEEP_county_source_matrix.json` (all 254 range-probed live) and the Kenedy proof.

## The population

| Group | Counties | Download |
|---|---:|---:|
| Degree-vintage, ingestible today | **177** | 4.01 GB |
| 202505 vintage, needs the reprojection flag | **57** | 0.246 GB |
| Dead at source (Donley 48129, HTTP 404) | 1 | n/a |
| **Total unloaded** | **235** | 4.26 GB |

Median degree-vintage archive is 10.66 MB. The 50 smallest total 173.5 MB; the 100 smallest total 607.3 MB. This is not a bandwidth problem.

## What the Kenedy proof established (48261, live in production)

Dry predicted apply exactly (538 features, 2,400 rows, 0 deletes). Idempotent re-run held row count. Geometry sane: zero rows outside Texas bounds, bbox matching the Census header exactly. **7.3 seconds end to end** — roughly 0.5s parse, 6.3s DB write.

Two numbers that reshape planning:

- **Seam factor 4.46** (rows written per distinct feature) against the 1.07 metro blend. Rural counties write far more tile rows per parcel. Storage projections derived from the 19 metro counties are light by roughly 4x on ranch counties.
- **MultiPolygon rate 0.19 percent** (1 of 538), plus 1.30 percent with interior rings. Low, and consistent with the statewide 0.37 percent by count.

## The waves

### Wave 0 — clear blocker 1, then re-prove
Fix the loaded-record so it derives from the store rather than a hardcoded map. Then re-run Kenedy: the CLI must report `loaded before: yes` and the idempotent path must hold. Nothing else starts until this passes, because every later wave depends on knowing what is already loaded.

### Wave 1 — the 10 smallest degree-vintage (~17 MB total)
`48261 Kenedy` (already loaded, the control), `48173 Glasscock`, `48033 Borden`, `48359 Oldham`, `48393 Roberts`, `48345 Motley`, `48311 McMullen`, `48413 Schleicher`, `48205 Hartley`, `48017 Bailey`.

Purpose: prove the path repeats. Serial, attended, full verification on each — dry predicts apply, idempotency, geometry sanity, seam factor recorded. If wave 1 is clean, the path is repeatable rather than a one-off.

Measure here: per-county wall clock, actual bytes-per-row, and whether seam factor holds near 4.46 across different rural geometries.

### Wave 2 — degree-vintage counties 11 through 60 (~157 MB)
First parallel wave. Per the parallelism design (`_inbox/2026-08-08_PARALLELISM_design_proposal.md`): counties are PK-disjoint on `txgio_parcel`, so county-level isolation is safe for L2 ingest. Recommended start is **8 concurrent** on the txgio store; connections are not the ceiling (max_connections 901, ~17 in use), so the real limits are WAL and row contention, neither of which applies across disjoint counties.

Attended. Halt the wave on any dry/apply mismatch.

### WAVE 3 IS HELD — operator ruling 2026-08-08

Waves 0 through 2 completed cleanly: **79 distinct counties now in `txgio_parcel`, up from 19**. Dry predicted apply on every one of 60 counties, idempotency held per county, zero out-of-Texas rows, and the adversarial pass returned NOT REFUTED with named conditions. The wave lane's own verdict was "ready for operator go."

Wave 3 is held anyway, for a reason the wave lane could not see.

**The `parcel-node` writer asserts false cross-vintage identity.** `plan-county-parcel-nodes.ts:445` mints `parcelKey: "_feature-${featureIndex}"` for parcels with no resolvable `prop_id`. That synthetic key lands in `atom_did`, and the writer upserts on `atom_did`. `featureIndex` is a shapefile sequence number and is NOT stable across StratMap vintages — so on re-acquisition, `_feature-7` from a new vintage upserts onto `_feature-7` from the old one and silently asserts they are the same parcel. Verified at source by the master planner. Found by the consumption-contract adversarial review (verdict: PARTIAL HOLD WITH FATAL GAPS, 2 fatal / 2 gap / 1 holds).

Wave 3 is new counties rather than re-acquisitions, so it is technically safe. The writer following behind it is not. Racing acquisition ahead of a defective seam is how geometry accumulates that the manifest cannot honestly count.

**Gate: orphan retirement, the `_feature-*` carve-out, and the C1/C5 warm preflight gate must ship before Wave 3 runs.** Do not re-acquire any warmed county until they do.

### Corrections from waves 0 through 2 (supersede the projections above)

- **Rural seam factor is 2.27 mean, not 4.46.** Kenedy was an outlier. Wave 1 ranged 1.518 to 4.461 with half the counties under 2.0; Wave 2 averaged ~1.52. The blanket 4x rural multiplier in the storage projection above OVERSTATES. Use the measured mix.
- **`TXGIO_COUNTIES` is still 19 while the store holds 79.** The CLI is now honest (loaded-status derives from store row count via `storeLoadedLabel`, PR #399) but product composition is still blind to 60 loaded counties. Open debt, named by the adversarial review.
- **TLS recipe for Windows:** `NODE_OPTIONS=--use-system-ca` PLUS a library browser UA. The env flag alone is not sufficient.
- **Execution-tree hazard:** waves ran from a separate clone (`legacy-design-tools-wave0`) because the primary checkout carries other lanes' branches. Run only from a clean tree at or after `fb6a42b2`.
- **Per-county cost is NOT obtainable** without inventing a billing API. The sub-200-dollar commitment remains unverified against real acquisition.
- Idempotent-replace table bloat and the vacuum policy are still open. Donley's source decision and Bosque's solo run are still owed.

### Wave 3 — remaining degree-vintage (~117 counties, ~3.8 GB)
Unattended-capable if waves 1 and 2 are clean and blocker 2 (TLS) is resolved. Largest members are the metros: Harris 479 MB / 536k parcels, Fort Bend 201 MB, Montgomery 194 MB, El Paso 192 MB, Brazoria 156 MB.

Run the five largest LAST and individually, not inside a concurrent batch — Harris alone is roughly 10 percent of the state's parcels.

### Wave 4 — the 57 on 202505 (~246 MB)
Requires `--reproject=3857` passed deliberately. Prove it on ONE county end to end first, exactly as Kenedy proved the base path. King 48269 is the natural candidate: it is already the reprojection test fixture and its converted bbox was verified against the Census extent.

### Never in an unattended batch
**Bosque 48035** — 104 MB for 19,975 parcels, 12x the median byte-per-parcel. Anomalous and unexplained. Run it alone and look at the result.

**Donley 48129** — HTTP 404 at source, the sole dead URL of 254. Not a wave member. It needs a source decision (alternate publisher, county direct, or honest absence recorded in the manifest).

## Verification per wave, non-negotiable

Every county, every wave: dry-run predicts apply exactly; idempotent re-run holds row count; zero rows outside Texas degree bounds; county bbox matches its Census extent. Any mismatch halts the wave rather than being noted and continued.

Per wave, record: wall clock, rows written, seam factor, MultiPolygon rate, and store size delta. These feed the storage projection, which is currently derived from metro counties and known to be light.

## What this does to the manifest

L2 completion moves Rail 1 (parcel geometry) from 0/254 toward 254/254. It does NOT by itself flip cells to satisfied — `parcel-node` atoms must be written from the loaded geometry, and nothing writes them yet (contract 1.13.0 and engine registration merged 2026-08-08; the writer seam exists, the writer does not). That is the joint between the statewide factory and the jurisdiction factory, and it is the next build after acquisition.
