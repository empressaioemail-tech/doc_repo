# What this image serves

Nothing in a multi-parcel result goes unnamed. The off-canvas list is no longer conditional on a canvas existing, so a result carrying more than one parcel accounts for every parcel in it. The lane widened this past the brief deliberately and was right to: naming only the undrawable ones leaves a drawable parcel unnamed whenever the panel happens to have painted a different one.

A paint-only neighbour preview. Hovering a door tooltip on a shared boundary may fetch that neighbour's stub rails without spending a turn, so a user can judge whether opening it is worth one. The two operator-ruled invariants are contract checks rather than intentions. First, a preview never claims to be in the conversation: every state carries the line "Not sent to the chat. Claude cannot see this." and is visually distinct from tool-result facts. Second, a preview can never pre-fill, populate or shortcut a turn; the Open control still drafts the ordinary message and the user still sends it, and three separate fixtures catch a violation.

Fail closed throughout, because `serverTools` is unverified. Every failure path states that no preview is available and why. Nothing renders empty rails, a dash, or a skeleton that reads as data, because a preview that silently shows nothing is indistinguishable from a parcel with no data, which is the confusion this program exists to prevent. Bounds: dwell 350 ms, timeout 4,000 ms, one preview in flight, one call per neighbour per panel instance.

A `tools=` token on the boot strip, following the p559 probe pattern including its marker comments so the `direct_network` contract stays armed.

# What the lane found in its own first pass, and why it matters

Three vacuous checks, all fixed before the second pass. Two contract rules were satisfied by a declaration rather than a call site, so `off_canvas_list_unbound` passed on the mere existence of `function offCanvasHtml(model) {` and deleting the call site did not fail it; both rules now read the emitted function body. A once-per-neighbour bound had two guards and the inner one was dormant, so deleting it broke nothing; it collapsed to one enforcement site that is now caught.

Separately, the lane found its own fixtures circular: they asserted the panel printed `app.PREVIEW_*`, comparing a constant against itself, which cannot fail if the constant is wrong. Rewritten with the sentences literal in the test and checked against the constants.

That is the fourth consecutive lane in this program to find at least one vacuous check in its own work. The pattern is now strong enough to state as an expectation in briefs, which is where it has been for the last two.

# Two limitations, declared

The `tools=` token does not answer "is the channel real" from a fresh panel. The panel makes no unrequested tool call, so the token reads `unread` until a door tooltip is hovered. What a fresh panel does answer is whether the host advertises the capability at all: `unsupported` is set as soon as the handshake settles without `serverTools`, including on error and with no host. The measurement therefore requires one hover, and the operator instruction says so.

`serverTools` itself remains unverified against this host. p559 measured `resources/read` through the bridge, which is a different method. The first hovered door on a live panel is the instrument.
