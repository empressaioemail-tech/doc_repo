# #175 deploy, 2026-09-18

## What ships and why it is not a fill-only deploy

`cloudbuild.parcel-record-fill.yaml` builds one image and redeploys four job definitions:
`factory-parcel-record-fill`, `factory-flood-ingest`, `factory-parcel-r4-companions` and
`factory-publish-gate-sched`. The gate scheduler is triggered hourly by Cloud Scheduler
`factory-publish-gate-sched-hourly` with `--apply` and writes `parcel_gate_verdict`, which
production reads, and there is no staging copy (fleet memory: deploying its image IS the apply).

Source: hauska-factory origin/main `85d63e8` ("fix(P-325): a join miss is not a verified absence
(#175)"). The live gate image is from `1fa850e7`. Between the two, the gate scheduler's own job file
and the vendored engine are unchanged; the one change on its path is `src/control/heavy-lease.mjs`
(P-307: a lease key names a real store host, and one Neon endpoint is one key). The fill job gains
#175 itself (a CAD join miss writes `unaccounted`, never `absent-verified`).

## Procedure and grading, pre-registered

1. Pause `factory-publish-gate-sched-hourly`. Let the running execution (`wv99r`, started
   14:00:04Z on the old image) finish rather than cancel it.
2. Snapshot `parcel_gate_verdict` (all rows) after `wv99r` completes: the pre-deploy baseline.
3. Build from a fresh clone at exactly `85d63e8`; confirm the four jobs carry the new digest,
   read by field.
4. Execute `factory-publish-gate-sched` once by hand with the scheduler's own args.
5. Grade: (a) the execution completes; (b) its heavy-scan lease is taken on the canonical host key
   `ep-round-base-au0jofwp.c-10.us-east-1.aws.neon.tech` (P-307); (c) every (county, rail) verdict
   and unaccounted count equals the baseline, because no cell was written between the two runs;
   only `evaluated_at` and `run_id` may differ. **Falsifier:** any verdict or count differing from
   the baseline, a lease under a non-host key, or a failed execution. Any of those stops the
   procedure with the trigger still paused, and it comes back to the operator.
6. Resume the trigger only on a PASS.

No `parcel-record-fill --apply` is run in this procedure.
