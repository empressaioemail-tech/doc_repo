# CP1: Red-card identity

Adversarial design before the implementers write. Read against origin/main `2ed062d` in the isolated tree.

## What is true in the code

1. `SearchBar` (`SearchBar.tsx:354`) owns `useState(initialValue)`. There is no `value` / `subjectLabel` prop. Map click never writes the input. Diagnosis section 6 stands.

2. `setSubjectByParcelNodeId` (`subject-store.ts:92-105`) awaits resolve, then `subjectStore.set` with no generation token. `adoptSubject` (`ExplorerMap.tsx:853-856`) already drops a stale sheet on the **card** via `inspectedRef`. The **store** still last-write-wins. Exports and compare read the store. That is the drainage-report class returning.

3. `runParcelLookup` (`ExplorerMap.tsx:980-1023`) always `inspectInPlace` + camera fit after resolve. No seq vs a later map click. Late Find snaps.

4. Existing `subject-store.test.ts` replaces subjects sequentially. It does not delay the first resolve. The last-write-wins hole is untested.

## Design (frozen for this card)

- Internal `subjectGen` on `setSubjectByParcelNodeId`. Increment at call. Set only if `gen === subjectGen` after await. Stale returns `{ kind: "stale", parcelNodeId }`. Failed / unplaceable still do not clear the standing subject.
- ExplorerMap `intentSeq` increments on map-click adopt and on each new Find start. `runParcelLookup` captures seq; after await, if seq moved, return without card/camera writes.
- SearchBar gains `subjectDisplay: string | null`. Parent subscribes to `subjectStore` and passes present situs, else parcel node id. Effect writes `value` only when the input is not focused.
