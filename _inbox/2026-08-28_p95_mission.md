### The five things that will catch you out

**A token-file edit alone changes colour and nothing else.** Every `--ss-fs-*` and
`--ss-h-*` token has zero consumers. The real type ramp is the `TYPE` object in
`src/styles/pe-chrome.ts` plus roughly 470 inline `fontSize` literals; the real
geometry is plain numbers in the `PE` object. If you grade item 3 by reading
`pe-tokens.css` you will report a no-op as done.

**Land the ramp in two commits, never one.** Values first, references second. The
references commit must produce zero visual change, so any pixel that moves in it is
a bug with an obvious cause. Bundled, a site that changes value and indirection at
once cannot be attributed, and 470 sites is too many to bisect by eye.

**122 standalone colour literals will desync on the swap**, plus 44 `var(--token,
<literal>)` fallbacks. They are decimal rgb triples inside template strings, so a
hex grep finds none of them. `StatusChip.tsx` passes the token for its label and a
hardcoded rgb for its fill; `StateNote.tsx` does it across all four registers. Fix
by DERIVING: `color-mix(in oklab, var(--ss-warn) 13%, transparent)` for fill, 34%
for border. Do not correct the literals one by one; a derived wash cannot desync and
correcting them once leaves the next palette change to correct them again. The
fallback form is banned outright.

**The gate sees 7.1% of the colour literals it appears to police.** That is P-96's
problem, not yours, but it means a clean gate run is not evidence your port is
complete. Grade item 4 on the VALUE SET across `src/`, not on the gate.

**Geometry is deliberately out of scope.** The ramp proves the pattern first.
Geometry tethering is P-96 item 8 and waits for your reference commit.
