# The unfixed list — every unfixed instance that would hit Burnet, Bell, or Milam

Every item below is `fix_status: unfixed` (or `ruled/unbuilt`, `fixed-undeployed`, `designed-not-landed` — read as unfixed at the customer-facing level, which is the level that matters) in the register, with the specific mechanism by which it lands on one of the next three counties. Register ids (`BLK-xxx`) are cited so each claim can be traced back to its source and evidence.

## Applies to all three counties, before any of them individually

These are pipeline-stage defects with no county literal in them — they would hit Burnet, Bell, and Milam identically, and in most cases would hit them FIRST, before any of the six control counties, because none of the three has ever been run through the pipeline even once.

- **The empty-county gate (BLK-017, BLK-018).** `evaluateRailGate` and `evaluatePopulation` both pass a completely empty county cleanly. Burnet's `parcel_record` reads 0 rows today; Bell's and Milam's are further behind still. Run any of the three through the current gate before stage 3 completes and it reads a clean pass — not because the county is done, but because the gate cannot tell "not yet filled" from "declared ahead." Designed 2026-09-13, confirmed not landed 2026-09-14, confirmed still the live defect 2026-09-16.
- **The six lease-less writers (BLK-019).** Owner, land-use, and flood-hazard (plus rail-corridor, RRC-pipeline, special-district) throw `LeaseRequiredError` on first write under the current lease code. Every one of the three counties would land missing these rails on day one unless this lands first. Directly named in the 2026-09-14 farm handoff as "Burnet without this fix lands missing three rails a customer asks about" — the same sentence applies unchanged to Bell and Milam.
- **False `absent-verified` on no-table/no-matcher/no-geometry (BLK-024).** The exact write path that produced 219,472 false setback absences across the six control counties has no county-specific logic — it fires identically wherever a city has no corpus table, which for Burnet is six of seven places (everywhere but Marble Falls), for Bell includes at minimum Temple (see below), and for Milam is presumptively all five towns, none of which has ever been probed.
- **The agValuation not-applicable sweep (BLK-267).** A dormant sweep exists that would write a false `not-applicable` across every county with no ag-valuation source wired — which today is every county except Williamson and Travis, meaning Burnet, Bell, and Milam all inherit this risk the moment anyone runs it, unless it is deleted first as the 2026-09-16 scope document's own L4 item requires.
- **The identity crosswalk gap (BLK-011, BLK-063, BLK-068, BLK-067).** The two-namespace identity rule (H1, generalized) has been run for exactly two of the six control counties (Hays, and Williamson is carded but not dispatched). Zero of the three next counties have been checked. Williamson's own number — 282,569 phantom nodes — is the standing warning for what an unchecked two-namespace county looks like at scale.
- **No retract-by-run-id (BLK-064).** If any of the three counties' first production publish writes something wrong, there is no mechanism anywhere in any of the four product repos to take it back — only a re-bake or a manual quarantine.
- **The stale-envelope-atom class at scale (BLK-264).** 490,185 atoms across the six control counties say "no buildable area" when the real cause is frequently "never re-derived after the ledger changed." A brand-new county's own first bake would mint fresh atoms rather than inheriting this specific stale population, but the SAME writer defect that produced it (a breadth-bake that writes a zero without a verified reason) is still live code and would produce the same class of false zero for Burnet's, Bell's, and Milam's own first envelope pass unless R4 (retire the mislabelled outcomes, writers can no longer emit `no-buildable-area` without a computed, verified zero) lands first.
- **Serial discovery via a sampled walk (BLK-087, BLK-013).** Unless the full-population census (checked in as `six-county-completeness.mjs`, generalized per the smooth path's C8-1) is extended to take an arbitrary county before Burnet runs, Burnet's own defects will be found one at a time by a 180-parcel sample, at the exact slow pace this register's own seventh-class finding names as the mechanism behind the whole program's history of surprises.

## Burnet (48053)

- **59,785 parcels on production against 50,138 ingest features (BLK-100-series context; measured directly in the 2026-09-16 scope document).** The two counts disagree and, as of 2026-09-16, nobody has reconciled them. This is not a hypothetical risk for Burnet — it is Burnet's own live, current, unexplained number. Three live hypotheses from elsewhere in this register are directly relevant: a multi-feature-per-account pattern (the Travis divergent-join class, BLK-036), a source truncation of the Harris shape (BLK-249, where a truncated input passed every existing gate including an independent SQL count because all four instruments read the same truncated table), or a genuine roll-vs-geometry vintage mismatch (the Caldwell-class CAD-cohort-vintage-drift, BLK-225). **The completeness check (P-194) exists for exactly this question and has never been run against Burnet.**
- **0 address points (confirmed multiply, most recently 2026-09-16).** Directly threatens the program's own Law 1 finish line — a real Burnet address must resolve via `scripts/surface-probe.mjs` for the county to count as done, and there is no address-point data to resolve against yet. The fix is scoped as "one loader run from the statewide StratMap set the six counties already use" (not a new acquisition), but as of this report it has not run. The wave-6 register also separately flagged this exact gap as a warning for Burnet's loader design (BLK-083) before any fix was scoped.
- **Marble Falls has a verified-live zoning layer (261 features) but no setback table (2026-09-16).** Marble Falls is simultaneously Burnet's best-positioned place (the only one of seven with real zoning data) and still blocked on the MAKE side — a table has to be built from the ordinance, not merely acquired. This is a straightforward S3-class acquisition item (per the smooth path and the 2026-09-16 scope document's own S3 worklist), not a code defect, but it is squarely unfixed and it is the one place in Burnet that could otherwise draw a real envelope.
- **The roster's NOT-FOUND-UNKNOWN-WHY status is desynced from reality (BLK-060).** Every Burnet place, including Marble Falls, currently reads this status despite Marble Falls independently carrying `verified-live` and a positive feature count on the very same row. This was first found as a general defect (falsifier F5, 2026-09-13, 12 of 23 zoning-wired cities affected across the roster generally), re-confirmed specifically for Burnet on 2026-09-14, and confirmed unfixed again on 2026-09-16 (pickup list item C11: "not started"). **A future agent or operator reading only the status field for any Burnet place will draw the wrong conclusion**, exactly as the farm handoff document itself warns.
- **The Burnet geographic-adjacency rationale is imprecise (BLK-066).** A minor, non-blocking item: OPS-24's original stated reason for choosing Burnet ("borders the six and is in none of them") does not hold as literally worded — Burnet borders only 2 of the 6 control counties. Does not disqualify Burnet; listed here because it is technically still an uncorrected claim in the program's own planning text as read by this lane.

## Bell (48027)

- **Temple is zoned and published on municode, but no public zoning layer has ever been found (BLK-102).** First recorded as a source gap 2026-07-24; still open more than seven weeks later as of the sources this lane read. This is not a paging bug or an acquisition-code defect — genuinely no ArcGIS/GIS layer exists publicly for Temple's zoning. It is named directly in the 2026-09-16 program scope document as "the largest acquisition question in Phase 2" for Bell. The only path forward is new-source research (municode text extraction, city PDF zoning maps, or a declared-unacquirable decision per the 2026-09-16 decision's own city-acquisition standard: log every source tried — city GIS, municode, eCode360, American Legal, city PDF, county appraisal zoning fields — before declaring unacquirable).
- **A boundary divergence: 694 Bell parcels sit fully outside the Census-defined county line (BLK-101).** Forensically confirmed 2026-08-08: the appraisal district's own roll includes parcels up to 5.9 miles north of the Census boundary, ruled to be an upstream CAD-jurisdiction reality rather than a pipeline defect (all four alternate hypotheses — projection, ingest, coordinate corruption, and a boundary-source error — were explicitly measured and ruled out). Practical risk is bounded (all 580 usable overflow parcels already carry declined envelope atoms) but unaddressed: any future ring computation for those 694 parcels needs an explicit exclusion, and zoning facts for them are keyed under a county that may not be the customer-facing answer a Bell resident expects. **No reconciliation mechanism exists; the ruling accepted the divergence rather than fixing it.**
- **Geometry ingest has not run for Bell at all (per the 2026-09-16 pickup list).** Distinct from Burnet, which has ingest data to reconcile — Bell has none yet. Two internal sources also disagree about Bell's state (one card claims "165,574 parcels, certified 20/20 on 2026-08-05," a figure the pickup list flags explicitly as needing to be measured fresh before being trusted, not assumed) — itself an instance of the same "closed at the gate, unverified at source" pattern (class C16/C18) this register found repeatedly elsewhere (see the HAYS-CERT-CLOSED case in the class table's falsifier-2 discussion, where a similarly-worded "certified" claim was directly contradicted by a defect that bit a month later).
- **Killeen and Belton are the only wired candidates; nine smaller places are unprobed absences.** Not a defect in themselves (an honest `searched-and-absent` state, per the Thrall precedent this program has already ruled correct behavior), but it means Bell's real place-level coverage work is almost entirely undone, same as Burnet's.

## Milam (48331)

- **The CAD REST endpoint is unproven, not merely unreachable (BLK-069's classifier definition, applied directly).** `rest-unproven` is a specifically-defined third state, distinct from both `rest-reachable` (176 of 254 counties) and `rest-absent` (58 counties, no URL at all): a URL is on file but no query against it has ever succeeded. In plain terms: **nobody has ever gotten a real answer out of Milam's CAD source.** The pre-bake audit (P-188/P-2 in the smooth path) will very likely read RED on Milam for exactly this reason, per the 2026-09-16 scope document's own prediction ("the pre-bake will likely read RED on it first").
- **Geometry ingest passed (20,992 features) but this is the StratMap geometry pipeline, a separate track from the CAD roll/attribute pipeline that is unproven.** A county can have valid parcel shapes with no verified way to get tax-roll values, owner names, or land use onto them — which is precisely Milam's situation today, and precisely the shape of defect that produced the Wood/Henderson/Liberty near-miss elsewhere in this register (BLK-252), where a geometry-only view of a county nearly caused real records to be silently dropped because the attribute side wasn't checked with the same rigor.
- **Five towns, none probed.** Milam has the least place-level work of any of the three counties — not even a first zoning-layer search has been logged for any of its towns, as far as the sources this lane read show.
- **Milam and Bell are explicitly scheduled to run together, in parallel, through the same farm (2026-09-16 ruling), after Burnet alone.** This means every unfixed cross-cutting item above (the empty-county gate, the lease-less writers, the identity crosswalk gap) must be fixed once, not twice, before Phase 2 starts, or the two counties will independently rediscover the same classes at the same time — which is exactly the risk the 2026-09-16 decision names as the reversal criterion for running them in parallel at all ("if Burnet's run shows the upstream fix rate exceeds what the integration seat can absorb").

## What is explicitly NOT on this list, and why

Per the 2026-09-16 decision, `agValuation` is now Texas-wide by ruling — so Burnet/Bell/Milam not having ag-valuation coverage is not itself an unfixed-list item; it is expected pending L4's acquisition work, distinct from the DEFECT (the dormant sweep that would silently mislabel it as not-applicable, which IS listed above). Similarly, the six control counties' own remaining Phase-0 work (setback table reconciliation, road-node quality, the R0–R9 envelope-family items) is deliberately sequenced to finish BEFORE Burnet runs (the 2026-09-16 operator ruling: "complete the six onboarded counties first... before Burnet runs"), so those items are not re-listed here as Burnet-blocking; they are precondition work the operator has already scoped as gating Phase 1's start, tracked in the class table and the full register rather than duplicated here.
