# What this image serves

Two cuts in one deploy, because p565 merged on top of p564 and one image covers both.

Q1, the selector front door for ledger function 7. Until now an area was visible only if you already named its parcels and could not be asked for. `find_parcel` keeps its plain-query behaviour and gains `near: {query, radiusFt}` over `place/radius-search` and `street` over `place/street-search`. No new tool; the catalog stays at 13.

A 422 stays a refusal. The new routes return refusals as HTTP 422 carrying `gtmErrorBody("serve_refused", code, reason)`, not a 200 with a status field. `declarePlaceSearchRefusal` turns that into a declared refusal with its display string, kept distinct from the generic error envelope. If `radius_unbounded` reached a user as "something went wrong", the whole reason the property seat made it a refusal rather than a truncation would be destroyed. A 400 is a caller bug and stays an error. Five closed codes mapped into the vocabulary, 19 rows to 24.

From p564: the node disposition union widened so a recognised claimed state is preserved rather than derived over; flood `zoneSubtype` reaching the report row so the 0.2 percent band and minimal hazard stop rendering identically; and label collision resolution that pushes labels apart rather than dropping one.

# THE DEGRADATION, DECLARED

**`near` is shipped and does not work.** The upstream `place/radius-search` route hangs. Measured through an authenticated call:

    400 validation path          0.17s      route reachable, routing fine
    valid params, radiusFt=500   504 @ 300s Cloud Run request timeout killed it
    valid params, radiusFt=50    same       not size-dependent
    street-search, same token    fast, hits not auth, and not the router

So routing and validation work and the query itself hangs. The MCP bounds its own call at 30,000 ms, so a user waits 30 seconds and gets an honestly declared upstream error rather than a hung panel, but the feature does not function. Filed for the property seat.

Shipped anyway, deliberately. Nothing that worked before this deploy regressed, `street` is pure gain, and holding p565 would not have fixed the upstream. Degradation is permitted when it is declared in the output, and this is the declaration.

Worth stating because it cuts the other way too: before p565 the assistant refused a radius ask immediately and correctly, because no read path existed. After p565 it waits 30 seconds and reports an upstream failure. For that one function the new state is SLOWER and no more useful than the old one, and it will look like a transient fault when the truth is a broken query. That is the cost of shipping the pair together and it is accepted, not overlooked.

# The gate caught a live outage, and that is the important part of this record

The FIRST canary of this image, `smartsite-mcp-00082-hab`, FAILED gate 2: `DATABASE_URL` resolved to `DEPLOYMENT_DATABASE_URL`rather than `DEPLOYMENT_DATABASE_URL_DIRECT`. Traffic was never shifted to it.

The cause was upstream of this deploy. `smartsite-mcp-00080-xum` was deployed at 13:49Z through the workflow, before LDT #564 merged at 14:13Z, and it wrote the pooler binding into the SERVICE SPEC. `gcloud run deploy --image` inherits that spec, so this canary picked up the bad binding without anything in the command asking for it.

**`00080-xum` was serving 100 percent from 13:49Z until this shift, roughly two and a half hours, with MCP writes broken the entire time.** Reads stayed green, `/health` answered `ok` throughout, and nothing alerted. `create_screen`, `save_property` and `set_property_status` were failing silently.

That is the SECOND service and the SECOND independent revert of the same binding in one day. The #564 workflow fix prevents the future case for both services; it could not retroactively repair a revision deployed twenty-four minutes before it merged. The only thing that caught this one was reading the secret binding before shifting traffic.

The repair was folded into this deploy: redeployed the identical digest with `--update-secrets DATABASE_URL=DEPLOYMENT_DATABASE_URL_DIRECT:latest` as `smartsite-mcp-00083-dun`, re-gated on binding, digest and health, other secrets confirmed preserved, then shifted.
