# Capital raise positioning

> **What this is.** The fundraising narrative layer: where Hauska sits in the funded category, the one-page investor summary, the investor archetypes most likely to write a check given mid-2026 capital flows, and the honest gaps to close before going to market. It is the companion to [`HAUSKA_INVESTOR_BRIEF.md`](HAUSKA_INVESTOR_BRIEF.md), which is the verified development snapshot (status, not narrative). When this doc states a number it carries the brief's verified figure; the brief is the source of truth for state and this doc is the source of truth for story. Both must agree before any external share.

> **Market basis.** Mid-2026 venture research: AI startups captured roughly 34 percent of global VC dollars in 2025, about 89 billion. 2025 was the weakest fundraising year in a decade at 66.5 billion across 558 funds, so dry powder concentrates in fewer, larger, later deals and early-stage undifferentiated SaaS is starved. Capital is concentrating in AI-native vertical software with verifiable outputs, agentic infrastructure, and physical-world applications. This is third-party market context, not an internal claim.

## Positioning narrative

Hauska is AI-native vertical infrastructure for the physical built environment, not horizontal SaaS with a model bolted on. The product does not exist without the model, and the model does not produce a sellable output without the proprietary structure underneath it. When an architect or an agent asks Hauska whether a building detail complies, the system does not return a copied passage of code. It returns a reasoning chain: which standards apply, how they reconcile against each other, which one governs, the specific source citation behind each step, a confidence score, an edition, and a verification state. That output shape is the product. A generalist investor recognizes this immediately as the funded category, because it is the difference between a passive copilot that summarizes documents and an agentic system that produces a verifiable, defensible answer a professional can act on and an agent can transact against.

What makes Hauska verifiable in a way an investor can underwrite is that verifiability is enforced in code, not promised in marketing. Every atom carries source attribution, confidence, timestamp, and edition. The system is built to refuse rather than to guess: it rejects wrong-edition matches and will not present an unverified web source as authoritative. There is a working demonstration of the hardest version of this problem, multi-standard reconciliation, where the engine combines ICC A117.1, the ADA, and FHA design requirements, determines that the most stringent rule governs a given clearance, cites all three standards, and reports a confidence of 0.91. That is the capability buyers in this space have never been able to buy, because the code text alone does not tell you what governs when three codes collide. The code tells you the rule. Hauska tells you what it means for your building, reconciled with every other code that applies.

The non-commoditizable part is the reasoning corpus and how it compounds, not the underlying code text, which is commodity and in places copyrighted. Hauska deliberately does not hoard verbatim code; it serves code by deeplink or licensed display and stores only the reasoning, citation, and structure atoms. A competitor can scrape the same public code. What they cannot replicate is a growing, calibrated body of reconciliation reasoning that improves as it is used, because each review feeds a calibration loop that tightens confidence over time. The atoms are AI-accessible and portable by design through a published contract, `@hauska/atom-contract` at version 1.3.0, with a five-value access policy that lets the same substrate serve a free public tier, a paid tier, and private tenant data without forking the architecture. The Hauska MCP gate already exposes 46 callable tools across three products, tier and entitlement enforced at call time, which means the substrate is built MCP-first for agent consumption rather than retrofitted.

This is also where the physical-world thesis and the agentic-infrastructure thesis meet in one company, which is rare and is what makes Hauska hard to slot as just one more vertical app. The buyer is the agent operator as much as the human professional. The same reasoning atom that powers an architect's compliance review is the unit an external agent pays to consume through the MCP gate, settled on a USDC rail that is built and tested on chain. Hauska is positioned to be the canonical, verifiable data and reasoning substrate for jurisdictional intelligence about the built world, sold by the reasoning rather than the raw data, which is precisely the category absorbing capital while undifferentiated SaaS starves.

## One-page investor summary

Problem. Determining what building codes and regulations actually require for a specific project in a specific jurisdiction is slow, expensive, error-prone, and fundamentally non-portable. Code is fragmented across thousands of jurisdictions and multiple overlapping standards, much of it locked in PDFs and paywalled databases. When standards conflict, which is constant in accessibility, life-safety, and zoning, a human professional has to manually reconcile them, and the answer lives in that person's head rather than in any system. Existing software returns documents, not answers, and nothing returns an answer an autonomous agent can trust and transact against.

Solution. Hauska converts jurisdictional code and property data into structured reasoning atoms, each carrying its source citation, confidence score, edition, and verification state, exposed through a published atom contract and an MCP gate built for agent consumption first and human interfaces second. The system does not store or sell raw code text. It sells the reasoning: which rules apply, how they reconcile, which governs, and why, with every claim traceable to a source. A working precedence engine already reconciles ICC A117.1, the ADA, and FHA requirements and reports which standard governs with cited confidence. The substrate powers three product surfaces: Cortex for design and plan review, Codex for code lookup, and SmartCity OS for cities.

Wedge. Two anchors prove the two sides of the model. Bastrop, Texas is the pioneering anchor city, with SmartCity OS running in production and serving the city real operational data, proving the city-customer side of the model as a SmartCity OS customer and design partner. Mox, an Austin multifamily operator running roughly 300 people across 45 locations and 12,000 units, is the scoped-tenant commercial wedge, entered through an operational pain point rather than through parcel intelligence. Alongside these, a web-first version of Cortex is designed so any architect anywhere can run a grounded, cited review in their own jurisdiction with no onboarding, which opens a launch to a community of roughly 7,000 architects without pre-ingesting the country.

Market. The funded category is AI-native vertical software with verifiable outputs and physical-world applications, which absorbed the dominant share of AI venture dollars through 2025. Hauska sits at the intersection of three live theses: AI-native vertical infrastructure, agentic infrastructure and the payment substrate for agents, and physical-world applications. The addressable surface spans architecture and engineering firms, real estate operators, and the municipalities that produce the underlying authority, with the agent operator as a net-new buyer category.

Business model. Tiered access on one rule. Layer 1 is free, bare reference atoms and bulk export built for distribution and developer pull. Layer 2 is paid, context-enriched reasoning metered per call by default with an optional stream subscription at volume. Every output at every tier carries its reasoning chain, citation, confidence, and timestamp. Take rate is settled in a 1.5 to 2.5 percent range depending on transaction type, below the card-processing benchmark and far below app-store economics, with the exact number set at the first paid call; the optimization target is volume and adoption, not rent per transaction. Payments settle on a USDC rail through Circle, with the crypto rail already built and tested and the fiat rail scoped. Supply is public model code, served by deeplink or licensed display (ICC / NFPA) and never hoarded as verbatim text; the compounding, non-commoditizable asset is the calibrated reasoning over that code, not the raw data. The unit-economics governor is under 200 dollars of compute plus one hour of human review per new jurisdiction onboarded, with a hard kill if that does not hold; that checkpoint is cleared. (Tier-count note: the development snapshot describes a third tier of integrated workflows on the same substrate, while the canonical tier doc [`08_tiered_access_model.md`](08_tiered_access_model.md) and CLAUDE.md frame two layers. The reasoning contract holds identically at every tier either way; the two-versus-three reconciliation is flagged in the gaps section and routed to a pricing-framework pass, not settled in external positioning.)

Why now. Agentic AI has moved past passive copilots into systems that produce actionable, verifiable outputs, and capital has concentrated exactly there while generic SaaS has dried up. Agents now need machine-consumable, citable, payable sources of physical-world truth, and that substrate does not exist yet. Hauska is building it MCP-first, with the reasoning corpus already live across 34 jurisdictions in the committed snapshot and a published contract that makes the data portable by default.

## Investor archetypes

The three archetypes below are the most likely to write a check given mid-2026 capital flows, with what each needs to see before moving.

The AI-native vertical software fund. The thesis-driven seed-to-Series-A investor backing applied AI in regulated, document-heavy industries such as proptech, contech, and govtech. This is the most natural fit. Before they move they need to see that the reasoning moat is real and compounding rather than a thin wrapper on a frontier model, which means usage and retention from the architect wedge, evidence that the calibration loop measurably improves output quality over time, and a credible revenue motion with early conversion data from free to paid. They will probe the sell-reasoning-not-data claim hard, so they need the refusal behavior and the multi-standard reconciliation working live, not on a slide.

The agentic-infrastructure and developer-tooling investor. The picks-and-shovels-for-agents thesis that increasingly also funds the payment and settlement layer for autonomous agents. For them the MCP-first architecture and the atom contract are the story. They need evidence that agents actually consume the catalog, meaning real MCP call volume and at least a few paying external API consumers, and the take-rate and metering model demonstrably working end to end including settlement. They will want to understand why the atom contract has a chance to become a standard others build against rather than a proprietary format only Hauska uses. Defensibility for them is adoption and network position, not corpus size.

The physical-world vertical investor. The proptech, contech, or govtech-focused fund, often paired with strategic or civic-minded angels who understand the built environment and know how hard municipal data and trust are to acquire. For them the partnership-first city model and the Bastrop anchor are the differentiator. They need repeatable onboarding economics, specifically the sub-200-dollar one-hour-per-jurisdiction number validated across more than one city, at least one signed partnership or revenue-share agreement or a design-partner letter of intent beyond Bastrop, and a clear answer on liability and regulatory posture for code-compliance outputs since a wrong compliance answer carries professional risk. Mox converting from engagement plan to signed pilot would speak directly to this archetype's commercial-traction bar.

## Gaps to close before going to market

The verifiable-output claim, the spine of the entire pitch, is now provable on a live production run. As of the 2026-06-09 cross-repo recon ([`_research/2026-06-09_cross_repo_recon.md`](_research/2026-06-09_cross_repo_recon.md)) the keystone has executed end to end in production: a real plan review on the Miami permit produced a web-grounded, cited finding against Florida Building Code 2023 Mechanical M601.6, drawn from a reasoning atom, which mock cannot fabricate. The deploy that makes this durable is live, not pending: cortex-api revision `00140-dax` serves 100 percent of prod with the finding mode set to anthropic and orchestration on, and the workflow hardcode that previously reset findings to mock on every deploy was fixed and held through the subsequent deploy. The earlier launch-blocker framing in this paragraph is obsolete. What remains is not provability but quality: the proven finding loosely conflated egress with mechanical, so finding-quality tuning is the open work, not the existence of a verifiable production output. This correction postdates both the 1 June development snapshot and the 2026-06-09 origin draft of this doc, which described the gap as still open.

The corpus numbers need disciplined framing or they backfire. The honest figure is 34 jurisdictions and roughly 21,100 atoms in the committed snapshot (2026-05-26), of which only two jurisdictions and about 478 atoms (Bastrop and Grand County) are public-free and the other 32 are platform-internal inventory. The public-versus-internal split must travel with every external number; the bare headline invites a diligence finding that the public, defensible catalog is far smaller than implied. The sourcing posture of the 32 platform-internal jurisdictions was not established in the cross-repo recon, so it cannot currently be asserted, which matters given the partnership-first commitment. A clean provenance answer is owed before anyone audits it.

Several claims are real as capability but thin as traction. Bastrop is live as a deployed platform, but a signed partnership-with-revenue-share agreement that proves the licensor model is not yet on file. Mox is an engagement plan, not a signed pilot or revenue. The sub-200-dollar one-hour onboarding economic is a cleared target and a decision rule, not yet a measured result across multiple jurisdictions, and the physical-world archetype will ask for the measured number. The roughly 7,000-architect community is an access channel, not committed users. No external customer has paid for a metered call yet; first money is intended to run through a manually reconciled pilot before the rails carry production traffic.

There are architecture and posture gaps a technical diligence pass will surface. Cortex has no user authentication and no data isolation today, so the self-serve layer the launch narrative implies is a real unbuilt build, not a flag flip, and should be disclosed honestly. Live production state at the MCP gate host was not independently verified in the recon. The payment substrate is partially real: the crypto USDC rail is genuine and tested, but the fiat Circle rail is a placeholder checkout function and revenue routing or splitting does not exist in code yet, so any claim about revenue share flowing automatically is aspirational. The regulatory and liability posture for compliance outputs and for moving money on regulated paths is open, sequenced against an IP attorney memo and Tech E and O insurance routing that have not closed (tracked in [`72_hauska_inc_operations.md`](72_hauska_inc_operations.md)).

Two reconciliation items before external share. First, the tier model: the development snapshot describes three tiers while [`08_tiered_access_model.md`](08_tiered_access_model.md) and CLAUDE.md describe two. Pick one articulation and make it consistent everywhere before it appears in investor materials. Second, the four-commitments framing: external drafts have referred to the four structural commitments as "AI-accessible, verifiable, integrative, portable by default," which are atom design properties, not the canonical four in CLAUDE.md (sell reasoning not data, partnership-first sourcing, cost per jurisdiction, dual interface). Going to market with two different sets of four invites a diligence inconsistency; settle on one before the raise.
